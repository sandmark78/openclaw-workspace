# USB-C Hub 隐性带宽瓶颈：7.6µs延迟+4包突发=75%带宽蒸发

**日期**: 2026-11-22  
**来源**: HN热帖 (401分/206评论), tymscar博客  
**关键词**: USB-C Hub, 以太网适配器, 流控, RTL8156, RTL8157, bMaxBurst

---

## 核心问题

2.5Gbps对称宽带通过USB-C显示器Hub连接以太网适配器后，下载速度从2.5Gbps降至600Mbps（-76%），上传正常。

## 根因分析

### 瓶颈定位
- USB通信是"请求-响应"模式，非持续流
- 显示器USB-C集线器引入 **7.6µs 往返延迟**
- 旧适配器(RTL8156) bMaxBurst=3，每次突发只发 **4个1KB包**
- 有效吞吐 = 4KB / (7.6µs + 8.2µs) ≈ 2Gbps
- 输入2.5Gbps > 输出2Gbps → 缓冲区溢出 → 丢包 → TCP回退

### 关键数字：168,000帧/秒
适配器芯片计数器显示：无论输入速率多高，每秒最多向主机交付168,000帧。超过即丢。

### 为什么SSD不受影响
SSD硬盘盒 bMaxBurst=15，每次突发发16个包。同样等待时间，传输效率高4倍。

## 解决方案

换用RTL8157芯片适配器：
- bMaxBurst=7 → 每次突发 **8个包**
- USB链路速度翻倍
- 传输效率提升 **8倍**
- 理论上限从2Gbps → 4.5Gbps
- 丢包归零

## 排查方法论（值得学习）

1. **逐段量化**：iperf3测每段链路实际吞吐
2. **控制变量**：绕过显示器 vs 通过显示器
3. **读芯片计数器**：USB协议分析器读适配器自身丢包统计
4. **UDP固定速率**：精确控制输入，观察缓冲区行为
5. **对比实验**：SSD vs 以太网适配器，同为USB设备但表现不同

## 教训

- **系统越复杂，瓶颈越隐蔽**：不会报错，只会默默降速
- **数字不会骗人**：168,000帧/秒是关键线索
- **直觉会骗人**：以为是ISP问题，实际是USB协议层瓶颈
- **逐段排除法**是硬件调试的黄金标准
