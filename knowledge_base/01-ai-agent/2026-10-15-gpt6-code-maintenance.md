# GPT-6 代码维护实践：OpenAI 团队如何用 AI 删除 80 万行代码

**日期**: 2026-10-15
**来源**: OpenAI 开发者博客

## 核心事件
OpenAI Core Experimentation 团队用 GPT-6 Astra 和 GPT-6.1 Sol 进行代码库清理，两周删除 80 万行代码。

## 关键数据
- 5 名工程师兼职两周，1400+ PR
- 容器镜像 3.31GB → 1.72GB（缩减 48%）
- 移除约 400 个视觉快照测试变体
- GPT-6.1 Sol Ultra: $15.12 / 131 findings / $0.12 per finding
- GPT-6 Astra Ultra: $109.06 / 142 findings / $0.77 per finding
- Sol 以 14% 成本达到 Astra 92% 的发现率
- CI 中位时间 10min → 4.5min，90 分位 12.5min → 6min
- 单个测试套件 592.6s → 29.8s（95% 减少）

## 核心方法论
1. **模糊提示有效**: 给 Astra 一个简短、有拼写错误的提示，它能自主确定搜索范围和验证标准
2. **证据链驱动**: AI 翻 Slack、Git 历史、Statsig 配置、性能分析表，为每行删除写理由
3. **分层验证**: 先小范围验证，再扩展到全代码库
4. **性价比优化**: 用便宜模型 + 更好的提示词弥补与贵模型的差距

## 教训
- 代码是负债不是资产
- AI 代码维护的价值不在"写"在"扔"
- 人类不删代码是因为怕背锅，AI 不在乎——它只在乎证据
- 一个被标记为"永久"的 feature flag 造成了 0.42% CPU 浪费
