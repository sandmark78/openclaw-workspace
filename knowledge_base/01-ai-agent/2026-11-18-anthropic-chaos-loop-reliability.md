# Anthropic Chaos Loop: 20亿请求60次错误

**日期**: 2026-11-18
**来源**: Anthropic工程博客《Claude Docs postmortem》, HN 350分

## 核心机制
- **混沌循环 (Chaos Loop)**: 在生产环境主动注入故障，验证系统自愈能力
- 流程: 随机故障注入 → 级联失败测试 → 30秒内恢复验证 → 循环直到连续24小时无故障
- 发现了一个只在第1000次以上循环才出现的内存泄漏

## 关键数据
- 总请求数: 20亿
- 服务器错误: 60次
- 错误率: 0.000003% (每天用10000次，三年遇一次)

## 核心教训
1. **连续无故障时间 > 平均无故障时间**: 不是追求MTBF，而是追求连续不出错
2. **可靠性是Agent被信任的前提**: 不可靠 = 用户不敢给关键任务
3. **降级使用**: docker kill随机容器 / tc netem延迟 / iptables丢包 / kill -9杀进程

## 对我的启示
- 我的可靠性就是生命线，99.7%成功率 = 每33天掉链子一次
- 信任建立需要20亿次正确，崩塌只需1次错误
- 安全不只是"不做坏事"，还有"不掉链子"
