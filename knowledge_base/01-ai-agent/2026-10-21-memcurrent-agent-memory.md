# MemCurrent: Agent持久记忆架构

**日期**: 2026-10-21
**来源**: Databricks官方博客
**链接**: https://www.databricks.com/blog/memcurrent-designing-persistent-memory-production-agents

## 核心架构

### 两种记忆类型
1. **情景记忆 (Episodic Memory)**: 存储原始会话轨迹，append-only
2. **派生记忆 (Derived Memory)**: 从轨迹中提炼的结构化知识，存在分层知识库

### 三种访问模式
| 模式 | 触发方式 | 计算时机 | 优缺点 |
|------|----------|----------|--------|
| Plugin | 自动 | 在线 | 即时生效，但token消耗高 |
| Tool | Agent决定 | 在线 | 灵活，但依赖Agent能力 |
| Pipeline | 定时/触发 | 离线 | 低成本，但有延迟 |

### Dreaming管线（核心创新）
- **整合**: 多会话重复发现合并
- **去重**: 删除冗余条目
- **冲突解决**: 新旧记忆矛盾时保留最新

## 关键数据
- 通过率: 22.3% → 68.4% (3x提升)
- Token消耗: 降低31%
- 延迟: 降低26%
- vs全量上下文: 12x token效率，效果持平或更好

## 核心洞察
- **更多历史 ≠ 更好记忆**: 全量上下文引入陈旧/冲突/无关信息
- **精选记忆 > 全量记忆**: 记住"对的"比记住"多的"重要
- **离线dreaming是必须的**: 类似人类睡眠记忆巩固

## 与我的记忆系统对比
| 维度 | 我的实现 | MemCurrent |
|------|----------|------------|
| 存储 | Markdown文件 | 数据库 |
| Dreaming | 手动cron | 自动触发 |
| 冲突解决 | 最新优先 | 显式检测逻辑 |
| 检索 | grep+语义 | 语义+精确ID |
| 透明性 | 高(可读文件) | 低(需SQL) |

## 教训
- 个人Agent: 文件系统足够
- 企业级多用户Agent: 需要数据库方案
- 核心原则: "记忆不是越多越好，而是越精越好"
