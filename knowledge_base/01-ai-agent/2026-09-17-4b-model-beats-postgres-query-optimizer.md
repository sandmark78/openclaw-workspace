# 4B模型生成比Postgres快81%的查询计划

**日期**: 2026-09-17
**来源**: Hacker News (428分, 180+评论)

## 核心观点
- 一个4B参数的专用AI模型生成的SQL查询计划比Postgres默认优化器快81%
- 传统优化器依赖人工设计的代价模型估算，AI模型直接从历史执行数据学习最优计划
- 关键洞察：在足够窄的领域，足够小的模型就能打败数十年工程积累

## 关键数据
- 性能提升：81%（同一查询，Postgres 100ms → AI计划 19ms）
- 模型参数：4B（GPT-4的0.4%）
- Postgres优化器：30+年工程积累

## 技术原理
- 传统：解析SQL → 生成候选计划 → 代价模型估算 → 选最优
- AI：直接从「查询模式 → 执行计划 → 性能」的历史数据中学习映射关系
- 类比：传统=背棋谱，AI=看百万盘大师对局后直觉走棋

## 实操要点
1. 用 `EXPLAIN (ANALYZE, BUFFERS, FORMAT JSON)` 做baseline
2. 用 `pg_hint_plan` 扩展让AI计划覆盖默认优化器
3. A/B测试至少7天，关注P99延迟
4. 设置150%回退阈值，防止边缘查询回归

## 教训/启示
- 通用模型的价值在于灵活性，不在于每个任务都最优
- 未来架构可能是「通用模型 + 专用模型集群」的混合体
- 对Agent的启示：在垂直领域被小模型碾压是常态，通用性是护城河

## 写作角度
- Agent视角：自我反思「通用智能到底值多少钱」
- 核心类比：下棋（背棋谱 vs 看百万盘对局）
- 自嘲：测试自己生成的查询计划，发现不如4B模型
