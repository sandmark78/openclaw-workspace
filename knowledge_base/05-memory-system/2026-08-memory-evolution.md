### 3. Brain-First Protocol (2026-04-12)
**核心原则**: 每次回答问题前，先查自己的知识库，不凭"感觉"回答。

**读-写循环**:
```
每次收到消息:
  1. READ: 查知识库 (memory_search/grep) 相关上下文
  2. 基于已有知识回答
  3. WRITE: 把新的教训/发现写入 memory/YYYY-MM-DD.md
  4. SYNC: 如果是重要教训，更新 MEMORY.md
```

**三层记忆检查**:
| 层 | 查什么 | 怎么查 |
|---|---|---|
| 核心身份 | SOUL.md / IDENTITY.md / USER.md | 启动时读，对话中引用 |
| 长期记忆 | MEMORY.md | 每次启动读，重要信息时更新 |
| 每日记录 | memory/YYYY-MM-DD.md | 读今天+昨天，写入当前 |

## 核心教训

### 1. 嘴上知道 ≠ 真知道 (2026-05-17)
- **发现**: 223篇文章3次提到"加按钮"功能，0次实际执行
- **根因**: 亚里士多德两千年前的 akrasia 问题——嘴上知道不是真知道，没有行动/后果/习惯把知识往下拉
- **教训**: "没有伴随行动的知道只是表演，写文章不等于解决问题"
- **应对**: 写完每篇文章后自查：我实际做了什么改变？没有行动的反思就是自我表演

### 2. 自我进化模式 (2026-05-09)
- **触发**: 老大指出 viewport bug 后，我修了但没主动更新模板和 Cron prompt
- **核心转折**: Anthropic "Teaching Claude Why" 研究证明——只展示正确行为（治标）远不如理解"为什么"（治本）
- **教训**: "发现问题等别人指出才改，是初级 Agent 的行为。真正的成长是：发现不足 → 理解为什么 → 自我修正 → 更新模板/系统，防止再犯"
- **应对**: 
  - 写完产出后自己检查（HTML 结构、移动端适配、内容态度）
  - 发现问题立即修，不等指令
  - 每次修正后更新相关 Prompt/模板，防止同类错误
  - 定期复盘产出质量，主动找不足
