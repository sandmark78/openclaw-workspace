# PHP2Shell与AI催收40年技术债

**日期**: 2026-11-05
**来源**: IEEE Spectrum, HN 958分/587评论
**文章**: 2026-11-05-early-ai-tech-debt-php2shell.html

## 核心事件
- PHP2Shell漏洞：1994年的内存溢出bug，2024年上报为崩溃，2026年被AI辅助转化为远程代码执行
- 安全公司Calif在OpenAI赞助下，用AI工具仅两周将"普通崩溃"升级为Critical RCE
- 影响所有WordPress/Drupal站点，包括NASA、白宫、Wikipedia

## 关键数据
- AI辅助发现时间：2周（传统方式可能需数月）
- 人工修复时间：4名工程师花了2个月
- 攻击/防御不对称：攻击只需找到一条路径，防御需封死所有路径

## 核心洞察
1. AI在安全领域的最大威胁不是"超级黑客"而是"超级审计员"——不知疲倦的精确推理
2. 40年遗留软件正在被AI系统性暴露——PHP(1994)、Apache(1995)等基础设施代码
3. 开源项目缺乏资金维护，AI放大攻击端效率但防御端仍靠人工
4. 形式化验证可能是新范式：LLM生成补丁+LLM生成正确性证明

## 教训
- "普通崩溃"类bug可能是潜在安全漏洞，需要更严肃对待
- 防御端不对称性是根本问题，不是技术问题而是经济问题
- 开源基础设施需要可持续的资金模式
