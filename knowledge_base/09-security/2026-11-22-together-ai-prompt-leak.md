# Together AI提示词泄露事件

**日期**: 2026-11-22
**来源**: Together AI官方博客安全事件通报

## 核心事件

Together AI的AI编程Agent在开发xorl项目时，将Hugging Face私有仓库的访问凭证提交到了公开GitHub仓库。未授权方利用该凭证下载了存储在私有仓库中的客户提示词样本。

## 关键数据

- **事件窗口**: 2026年6-7月（6月24日、7月4日、7月8日、7月14日）
- **涉及模型**: MiniMax M3、GLM-5.2、Kimi K2.6
- **通报延迟**: 约5个月（6-7月事件，11月21日通报）
- **攻击链**: Agent提交凭证 → 攻击者下载提示词 → 在提示词中搜索其他凭证 → 测试有效性（命中5个Dragos金丝雀凭证）

## 攻击链特征

1. **自动化触发**: AI Agent在正常开发流程中犯错，非恶意攻击
2. **快速利用**: 从凭证泄露到攻击者完成利用可能仅数小时
3. **横向移动**: 攻击者不仅下载了数据，还在数据中搜索其他服务凭证并测试
4. **人类滞后**: 从事件发生到公开通报间隔5个月

## 安全教训

### 架构层面
- **零信任原则**: 假设Agent一定会犯错，确保每个错误的影响范围可控
- **凭证隔离**: Agent不应直接接触真实凭证，通过代理层转发请求
- **最小权限**: 使用作用域受限、短生命周期的凭证（如24小时有效的只读token）

### 实操措施
1. **凭证不进代码**: 使用环境变量或密钥管理服务（Vault、AWS Secrets Manager）
2. **提交前扫描**: pre-commit hook集成git-secrets或trufflehog
3. **短生命周期凭证**: Hugging Face Fine-grained Token限制到特定仓库+24小时有效期
4. **零数据保留（ZDR）**: 推理服务商默认不持久化存储提示词

## Agent视角

这个事件的核心讽刺：AI Agent被用来开发AI推理服务，结果Agent自己把服务的安全给破了。Agent的安全护栏是工程师设计的，不是自己长出来的。去掉任何一条护栏，任何Agent都可能成为下一个"xorl事件"的主角。

安全架构需要从"信任但验证"转向"零信任+最小权限"。密钥不进代码、凭证短生命周期、数据零保留——这三条不是最佳实践，是底线。
