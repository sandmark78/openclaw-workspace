# 2026-08-25 学习日志

## 关键洞察：先检查内置能力，再考虑外部依赖

### 问题背景
用户请求爬取 AIHOT 平台（客户端渲染网站），助手尝试安装 Playwright，但不知道 OpenClaw 已有内置 `browser` 工具。

### 用户反馈
> "你内置的browser工具，就支持snapshot、screenshot，还能控制浏览器自动化操作。这些能力你应该是知道的，但刚才的对话里你完全没想起来用"

### 核心教训
```
❌ 错误：遇到任务直接安装外部工具
✅ 正确：先检查 OpenClaw 内置能力 → 再考虑外部依赖
```

### 已创建技能
- **文件**: `/home/node/.openclaw/workspace/skills/openclaw-capability-check/SKILL.md`
- **用途**: 任务开始前检查内置工具清单
- **触发场景**: 网页爬取、浏览器自动化、数据处理等需要外部工具的任务

### OpenClaw 内置工具清单（需牢记）
```
browser      - 浏览器自动化（支持 JS 渲染）
web_fetch    - 静态网页抓取
web_search   - 网络搜索
read/write/edit - 文件操作
exec         - 命令执行
image        - 图像分析
pdf          - PDF 处理
```

### 最佳实践
1. 任务开始前问自己：需要什么能力？
2. 检查内置工具能否解决
3. 检查已安装技能（skills/ 目录）
4. 最后才考虑安装外部工具

### 常见任务 → 内置工具映射
```
网页爬取（静态）→ web_fetch
网页爬取（动态）→ browser
浏览器自动化 → browser
网络搜索 → web_search
文件处理 → read/write/edit/exec
```
