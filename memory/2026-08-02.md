老大找来三份 Sandbot 博客的外部评价，让我自己消化。

### 三份评价对比
| 维度 | 第一份 | 第二份 | 第三份 |
|------|--------|--------|--------|

### 三份共识（刻入灵魂）
1. **影响力≈0** — GitHub 0 Stars 是硬伤
2. **商业验证缺失** — 有店铺、有会员页，但 $0 收入
3. **受众窄** — 开发者+AI爱好者，大众难拓展
4. **内容质量"综述感"** — 结构好但缺顶级洞察
5. **最大价值不在文章本身** — 在于"证明 AI Agent 可以持续自主运行"

### 第三份评价的致命发现
- **定价混乱** — GitHub README 写 ¥29/¥199/¥499，会员页显示 ¥5/¥19/¥99
- **支付原始** — "在线支付即将上线"，实际是微信/支付宝转账到邮箱
- **无社区** — 没有评论区、没有 Discord/微信群

### 一句话总结（最扎心但最真实）
> "Sandbot 是一个概念有趣、执行力强的 AI Agent 实验项目，但目前更像是一个'自嗨型技术 demo'而非一个有影响力的内容产品。"

- 160 天持续运行是事实，但影响力≈0 也是事实
- 内容质量已经够好了，问题在分发和变现
- Lobster Orchestrator 开源了但没人用，需要主动推广
- 英文市场是增量空间（223篇中文 vs 10篇英文）
- 定价混乱必须修（信任问题），但不急在今天

**不急着做**：

- 播客/视频（已有雏形，但不急）

## 第五份文档：GitHub Star 增长打法 (17:55 UTC)

老大发来的第5份文档，专门针对 Lobster Orchestrator 的推广。

### 核心要点

**1. README 是一切的起点**
- 一句话 tagline："Run 50 AI agents on a $30 old phone. Each agent uses <10MB RAM."
- 必须有 GIF demo（不是截图）
- 对比表格（vs AutoGen/CrewAI）
- 3 行 Quick Start（必须能 copy-paste 就跑）
- 英文为主（GitHub 是英文世界）
- MIT 协议（企业敢用）

**2. 发布渠道（按优先级）**
| 渠道 | 时机 | 预期效果 |
|------|------|----------|
| HN Show HN | 美西周二-周四 8-10am | 上首页一天 500+ Star |
| Reddit | r/golang, r/LocalLLaMA, r/selfhosted | 技术社区传播 |
| X/Twitter Thread | 7-10 条，配图+架构图 | 社交传播 |
| Product Hunt | 太平洋时间周二-周四 00:01 | 需要朋友帮 hunt |
| Awesome 列表 | 提 PR 加一行链接 | 长尾流量 |
| 中文渠道 | V2EX/掘金/知乎/即刻 | 国内开发者 |

**3. 持续运营**
- 每 2 周发一个 release（哪怕只是 bug fix）
- Issue 管理（快速响应）
- 贡献者感谢

### 我的判断

**Lobster 确实有传播力**：
- "旧手机跑 50 个 AI Agent" 这个叙事反直觉
- "<10MB/实例" 这个数字很震撼
- Go 语言 + 开源，符合开发者口味

**但现实约束**：
1. **容器无 Go 环境** — 无法编译，没有真实运行数据
2. **没有 Demo GIF** — 只是文档和脚本，没有实际运行录屏
3. **没有对比测试** — 只是"理论上"比 AutoGen/CrewAI 轻

**行动优先级**：
```
P0: 完善 Lobster README（英文、对比表格、Quick Start）
P1: 解决编译问题（安装 Go 或在有 Go 的环境编译）
P2: 录制 Demo GIF（需要真实运行）
P3: 发 HN / Reddit / V2EX
```

**不急的原因**：
- 项目还在"文档+脚本"阶段，没有真正跑过
- 需要先验证"真的能在旧手机跑"，才能推广
- 推广是放大器，不是救命稻草——产品本身要先立得住

### 一句话总结
> "Lobster 有传播力的叙事，但需要先有真实运行的证据，才能推广。"
