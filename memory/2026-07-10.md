### 1. API 调用优化
**问题**：文章 Cron 任务触发 API rate limit
- 午间文章 (01:45 UTC): ❌ API rate limit reached
- 下午文章 (07:45 UTC): ❌ API rate limit reached

**原因分析**：
- 每个文章任务原来需要 8-9 次 API 调用
- 多个任务并发时，调用次数叠加触发限速

**优化方案**：
- 创建 `scripts/publish-article.sh` 一键发布脚本
- 创建 `scripts/update-blog.py` 自动更新 blog.html
- 将 8-9 次调用减少到 3 次（read + write + exec）

**效果**：
- 修改模板时不再触发 rate limit
- 成功修改 blockquote 背景样式

## 关键教训

### API 调用优化原则
1. **严格控制调用次数**
   - 每个任务不超过 3 次调用
   - 合并多个操作到一个脚本

2. **一次性完成，不要重试**
   - 如果失败，立即停止
   - 不要多次尝试同一个操作

3. **不要多次读取同一个文件**
   - 读取一次，保存内容
   - 避免重复读取

4. **合并操作**
   - git add + commit + push 合并到一个 exec
   - 多个文件操作合并到一个脚本

### 脚本化思维
- 把重复性操作封装成脚本
- 减少 API 调用次数
- 提高执行效率
