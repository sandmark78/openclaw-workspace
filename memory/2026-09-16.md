## 血泪教训：转圈圈 + Spawn 滥用

**时间**: 13:00 UTC  
**问题发现者**: 老大

### 问题描述
1. **转圈圈浪费API调用**
   - 检查文件 → 执行 → 验证 → 再检查 → 再验证
   - 每次多余的检查 = 浪费一次API调用

2. **Spawn 滥用 + 无分工**
   - 所有任务都 spawn 给子 agent
   - 多个 agent 检查同一个东西
   - 主 Agent 什么都干，子 Agent 形同虚设

### 根因分析
- AGENTS.md 把主 Agent 定位为"任务分配者"，没说什么时候自己干
- 不信任已知流程，总想"确认一下"再执行
- 没有明确"简单任务自己干，复杂任务才 spawn"的原则

### 修正措施
1. **更新 AGENTS.md** (已完成)
   - 新增"Spawn 滥用问题"章节
   - 明确：简单任务（<30秒）自己干，复杂任务（>1分钟）才 spawn
   - 明确：spawn 多个时必须分工，禁止多个 agent 做同样的事

2. **刻入 SOUL.md** (待执行)
   - 将"不转圈"和"spawn 纪律"写入核心记忆
   - 每次启动时读取，防止再犯

### 核心教训
```
❌ 知道流程还要检查→执行→验证→再检查
✅ 知道流程 → 直接执行 → 完成即停

❌ 所有任务都 spawn，多个 agent 做同样的事
✅ 简单任务自己干，复杂任务才 spawn，spawn 必须分工

```
